For the first test, we should deliberately avoid WordPress.

Give it something trivial such as:

“Create a Python project with a function, tests, README and run the tests.”

That proves our Tersuite ↔ OpenHands infrastructure works.

Then MVP-2 becomes:

Generate basic WordPress plugin

Then MVP-3:

Generate professional WordPress plugin

Then the knowledge system.

Then the sophisticated feature discovery experience.

This avoids the classic mistake of building WordPress intelligence, UI, billing, sandboxing, multi-agent orchestration and knowledge retrieval simultaneously before we know whether the underlying execution pipeline is reliable.

What I would consider the real Tersuite differentiator

Not:

“We use OpenHands.”

Nobody cares.

Not:

“We have AI agents.”

There are thousands of those.

The differentiation is:

Tersuite understands WordPress deeply enough to turn a vague idea into a professional, comprehensive product specification, obtain the user's approval, architect it correctly, build it, test it in a real WordPress environment, review its security, repair failures, and deliver an installable plugin.

That is the north star.

OpenHands gives us the engineering machinery.

Tersuite provides the WordPress intelligence and product-development system.
